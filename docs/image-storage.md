# Image storage for the next beta

New images use the `CLIPIMG2` format. A 16-byte framing header contains the format marker and two bounded encrypted-block lengths. It contains no clipboard text, paths or pixels, but reveals the record format and block sizes. Windows `CurrentUser` DPAPI protects metadata and encoded PNG independently. The metadata includes the clip identity and image fingerprint; reads verify both before handing decoded payload ownership to a caller.

The listener passes the existing PNG directly to DPAPI, then writes the header and encrypted blocks without assembling a second whole-record buffer. Metadata is bounded to 64 KiB; encoded PNG remains bounded to 16 MiB. Combined entry size still follows the history limit. Invalid/truncated frame sizes are rejected before payload allocation; metadata cannot embed a Base64 image. Rejected decrypted image bytes are cleared.

Older encrypted JSON records remain readable. Rewriting an old image, such as a star change, adopts the new format without changing its identity or original image bytes. Startup does not bulk-convert old images or decrypt their payloads when their small summary cache is valid. Enhanced records use `.clip2` (including snippets) so older builds ignore them rather than treating their bytes as damaged legacy `.clip` files. Older readers may delete optional summaries; the current app rebuilds those without deleting authoritative payloads. Downgrading/mixed-version use remains unsupported: older versions cannot display enhanced records or enforce their retention.

In a warmed local synthetic test of eight 2-MiB image-payload operations, legacy JSON encoding plus DPAPI allocated **44,749,872 managed bytes**. Complete binary writes, including metadata and filesystem work, allocated **16,988,056 bytes**. The comparison deliberately includes more work in the new path; it measures managed allocation, not native allocations, peak RAM or a captured-image soak. One encrypted payload occupied **2,796,630 bytes before / 2,097,916 bytes after**, about 25% less. Results vary with payload/metadata and runtime.

Unchanged history now reuses a structurally read-only ordered summary snapshot. Normal retention checks avoid sorting all eviction candidates unless capacity is exceeded. Search retains only bounded per-query result metadata; unchanged positive and negative results avoid repeated full-text reads. Body fingerprints, titles and labels invalidate those results. Closing releases the search cache. These changes do not remove WPF/native graphics allocations or replace installed-device performance validation.
